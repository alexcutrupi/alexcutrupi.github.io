01 / Hosting infrastructure & web platform

BlastHost

I developed and managed infrastructure for BlastHost, a hosting brand associated with InstantBay. The project brought together Linux servers, a custom website, game server management, billing APIs and an independent email server.

I personally configured servers, installed services, developed the frontend and troubleshot the connections between them, with infrastructure intended to support services such as Minecraft hosting.

The systems

What I worked on

Linux infrastructure

Administered a Debian 12 bare-metal home server, blasthost-node1, and used VPS infrastructure for public connectivity. Worked with Debian and Ubuntu, service installation, permissions, firewall rules and routing.

Game server management

Worked with an existing Pterodactyl installation on Ubuntu, explored its Laravel views and frontend assets, and created a BlastHost theme directory to customise the panel’s appearance and server layout. Also investigated adding AdSense to the interface.

Custom web platform

Built a Next.js frontend using JavaScript, Node.js, Tailwind-related tooling and Turbopack. Worked with Next.js 15.4.6 in August 2025 and 16.1.4 in January 2026, deploying with Nginx and a systemd service.

Billing API integration

Connected the frontend to the WHMCS API, using GetProducts in lib/products.ts to retrieve hosting packages. Troubleshot API IP restrictions. The full ordering, payment and provisioning flow was not confirmed complete.

Independent email server

Configured blasthost-mail with Debian, Postfix, Dovecot, MariaDB and Let’s Encrypt, using Swaks for SMTP testing. Fixed SQL-backed mailbox authentication and tested SMTP submission and STARTTLS.

Monitoring & firewall configuration

Installed and configured Netdata, inspected monitoring settings and investigated access restrictions for its dashboard. Used UFW rules while configuring server access and network services.

Connecting the infrastructure

Home server meets VPS

One objective was to route traffic from the home-hosted Minecraft infrastructure through a public VPS. This involved VPN tunnels, routing, NAT, port forwarding and firewall configuration.

OpenVPN
Installed the server on Debian and successfully connected from macOS, with the client reporting “Initialization Sequence Completed”.
GRE tunnels
Experimented with a VPS-to-home tunnel. The home interface reached an UP state, but VPS interface problems remained unresolved.
WireGuard
Configured a tunnel and full-tunnel routing, resolved a missing resolvconf dependency and got the service running. End-to-end traffic routing was not confirmed complete.

What I took from it

Working across the whole stack

BlastHost gave me practical experience connecting physical servers, network tunnels, databases, web applications and email services. Much of the learning came from reading logs, tracing network errors, fixing permissions and resolving build and service startup failures.

Several components reached working milestones while others were still being developed or troubleshot. This case study describes that technical work; it does not establish a commercial launch, completed billing system or the services’ current operating status.
